Title: Substitution
Snippet:
<sub alias="World Wide Web Consortium">W3C</sub>
Note:
The preferred way to correct a mispronunciation: say something differently than it's written.
[/Entry]

[Entry]
Title: Pronunciation (IPA)
Snippet:
<phoneme alphabet="ipa" ph="təˈmeɪtoʊ">tomato</phoneme>
Note:
IPA only. SAPI is accepted by Azure and sounds correct, but has no control over spacing/pacing between phones -- declined for that reason, not for being unverified.
SAPI only works on eight specific locales (en-US, fr-FR, de-DE, es-ES, ja-JP, zh-CN, zh-HK, zh-TW, per Microsoft’s docs — en-GB is not among them and fails outright). Combined with the lack of pacing control observed earlier, SAPI remains out of this panel; IPA works everywhere and is the only phoneme alphabet documented here.
[/Entry]

[Entry]
Title: Pause
Snippet:
<break strength="medium"/>
<break time="750ms"/>
Note:
Strength (measured once per keyword; consistent across locale and voice): x-weak ~180ms, weak ~410ms, medium ~700ms, strong ~915ms, x-strong ~1175ms.
[/Entry]

[Entry]
Title: Prosody (rate, pitch, volume)
Snippet:
<prosody rate="-10%" pitch="+15%" volume="+3">Slower, higher, louder speech.</prosody>
Note:
All three attributes are optional -- include only the ones you need. rate and pitch accept a percentage ("+15%", "-10%"); volume accepts a bare signed or absolute number ("+3", "-5.5", "90") or a keyword (loud, x-soft, etc.) -- a dB-suffixed value like "+3dB" matches the general SSML spec but not Azure's own implementation, and fails to synthesize outright. The app's own global speaking-rate setting (separate from this tag) is applied at composition time only -- never written into the saved document.
[/Entry]

[Entry]
Title: Digits
Snippet:
<say-as interpret-as="digits">1234</say-as>
Note:
Documented as digit-by-digit, but observed (Jenny en-US and Leah en-ZA) grouping 4-digit strings in pairs instead -- "1234" read as "twelve thirty-four," not "one-two-three-four." Verify by ear before relying on it.
[/Entry]

[Entry]
Title: Time
Snippet:
<say-as interpret-as="time" format="hms12">1:45pm</say-as>
Note:
Only reliable with 12-hour input and an explicit am/pm marker. A bare 24-hour value like "13:45" is read literally as "thirteen forty-five" regardless of the format attribute -- convert to 12-hour form before tagging.
[/Entry]

[Entry]
Title: Styled speech (mstts)
Snippet:
xmlns:mstts="https://www.w3.org/2001/mstts"
<mstts:express-as style="cheerful">Text.</mstts:express-as>
Note:
New documents declare this automatically. For a legacy document missing it, paste the declaration onto the <speak> tag by hand -- Omskep never adds it for you. Unsupported styles are silently ignored (text still speaks, plainly) on voices that don't support them.
[/Entry]
